# Dataset card: public Brazilian invoices (NF-e), product description -> NCM

[Português](DATASET_CARD.md) · **English**

Files generated by `make publish` into `data/publish/` (not versioned; PHASE 2 publishes them on Kaggle
and Hugging Face). This card accompanies the files. Back to the project: [README.en.md](../README.en.md).

## Summary

Line items from electronic invoices (NF-e, *Nota Fiscal eletrônica*) for Brazilian federal government
purchases, published by the Transparency Portal (CGU, the federal comptroller), with the **free-text
product description** written by the supplier and the **8-digit NCM** it declared. NCM (*Nomenclatura
Comum do Mercosul*) is the Mercosur product code, an extension of the international Harmonized System,
and it drives the taxes applied to each item. Main task: classify the description into the NCM (8
digits) or the chapter (2 digits). Possible secondary tasks: detecting classification inconsistencies,
normalizing descriptions, studying public spending by category.

- Rows: **3,094,298** items (six months, 2025-04 to 2025-09), 7,381 NCMs, 96 chapters,
  ~900 thousand distinct normalized descriptions.
- Language: Brazilian Portuguese (supplier text: abbreviations, upper case, typos).
- Formats: Parquet (ZSTD) and gzipped CSV, same columns.

## Source and license

- Transparency Portal (*Portal da Transparência*), dataset "Notas Fiscais", monthly download
  (`https://portaldatransparencia.gov.br/download-de-dados/notas-fiscais/AAAAMM`), files `NotaFiscal`
  and `NotaFiscalItem`. Federal government open data (dados.gov.br catalogue: ODbL, to be confirmed on
  the dataset page at publication time). This derived dataset keeps the license of the source data; the
  code that generates it is MIT.
- Suggested citation: Controladoria-Geral da União, Portal da Transparência, Notas Fiscais Eletrônicas
  (accessed November 2026); derived by Rafael Bueno, repository `raio-x-fiscal`.

## Privacy (LGPD, Brazil's data protection law)

Removed: the NF-e access key (it contains the issuer's CNPJ, the corporate taxpayer number), the
issuer's CPF/CNPJ and company name, state registration, the buyer's CNPJ and name, invoice number and
series. Kept: product description, NCM and its official description, CFOP (fiscal operation code),
unit, quantity, values, issuer and buyer state (UF), month and issue date. `item_id` is an md5 of
(access key, item number), not reversible without the key. The product description is free supplier
text and may, in rare cases, contain brand or personal names; no filter was applied beyond what the
source publishes.

## Columns

Column names are kept in Portuguese, as in the published files.

| Column | Type | Description |
|---|---|---|
| `item_id` | string | md5(chave_acesso, numero_produto); stable item identifier |
| `split` | string | `train` (2025-04 to 2025-07), `valid` (2025-08), `test` (2025-09) |
| `mes_referencia` | string | YYYY-MM of the source file |
| `descricao_produto` | string | supplier's free-text description, as published |
| `descricao_normalizada` | string | lowercase, no accents, only `[a-z0-9]` separated by spaces |
| `ncm_codigo` | string | 8-digit NCM, leading zero restored (**label**) |
| `capitulo` | string | first 2 digits of the NCM (coarse label) |
| `posicao` | string | first 4 digits of the NCM (heading) |
| `ncm_descricao` | string | most frequent official NCM description for the code |
| `cfop` | string | 4-digit CFOP (NULL if invalid) |
| `unidade` | string | commercial unit in upper case (`UNIDAD`, `KG`, `PEÇA`, ...) |
| `quantidade` | decimal(18,4) | item quantity |
| `valor_unitario` | decimal(18,4) | unit price in BRL |
| `valor_total` | decimal(18,2) | item total in BRL |
| `emitente_uf` | string | supplier's state |
| `destinatario_uf` | string | buying agency's state |
| `seen_in_train` | bool | for `valid`/`test`: the `descricao_normalizada` exists in `train` (NULL in training) |

## Splits and recommended protocol

**Temporal** split: train on earlier months, test on the most recent. The dataset ships every item
(with repetition) so each user can pick a deduplication policy; the recommended one is the baseline's:

1. training collapsed to one row per `descricao_normalizada`, label = most frequent NCM;
2. report the test on four slices: all items, unique descriptions, items with
   `seen_in_train = false`, and never-seen unique descriptions (the honest generalization number).

Known label noise: 3.6% of training descriptions appear with more than one NCM, accounting for 26% of
items; among test items with an already-seen description, the NCM matches in 86.5% of cases. The label
is what the supplier declared, not an audited ground truth.

## Baseline

TF-IDF (word 1-2 + character 3-5, 400 thousand dimensions) + hierarchical LinearSVC (chapter, then NCM
within the chapter), trained on 2025-04 to 2025-07, tested on 2025-09:

| Test slice | Chapter top-1 / top-5 | NCM top-1 / top-5 | NCM macro F1 |
|---|---:|---:|---:|
| All items (547,718) | 89.0% / 96.0% | 77.3% / 87.7% | 38.1% |
| Never-seen unique descriptions (126,723) | 79.7% / 92.4% | 60.0% / 76.1% | 26.5% |

Details and the comparison with exact lookup and the majority class in `reports/ml_results.md` (in
Portuguese).

## Limitations and biases

- Coverage: federal government purchases only, heavily weighted towards medical and hospital supplies
  (chapter 90), medicines (30), food (07, 08), books (49), machinery and electronics (84, 85). It does not
  represent retail or industry in general.
- Noisy label (see above). Very short descriptions ("VENDA", "SERVICO") are legitimately ambiguous.
- Six months of a single year; seasonality and NCM table revisions are not covered.
- Values are the ones declared on the invoice, with no deflation and no cross-check against budget
  commitments or payments.
